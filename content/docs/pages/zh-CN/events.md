# 交会事件

一个事件就是一个**交会**：两个物体、一次接近，以及它们之间的全部 CDM 历史。
它是人对人协同的单位；CDM 是机器计算的单位。

## 聚合

当两条 CDM 描述的是同一对物体在同一时刻的接近，它们就是同一个事件。重发一条新消息
不会产生新事件——这正是要点，否则一次被更新了六次的交会看上去就像六个问题。

配对不分方向：同一个交会也会以两个物体互换的形式到达，把它算成第二个事件会让每条
告警都翻倍。

## 字段

| 字段 | 含义 |
|---|---|
| `id` | 事件 |
| `created_at` | 事件首次建立的时刻 |
| `updated_time` | 最近一条 CDM 改动它的时刻 |
| `first_cdm_tca_gps_nanos` | 第一条消息给出的 TCA——估计从那以后移动了多少 |
| `object1_*` / `object2_*` | 参与方，含 `maneuverable` |
| `operator1_id` / `operator2_id` | 各自归属 |
| `claim_status_operator1/2` | 谁声明要机动 |
| `last_status_update_time_operator1/2` | 各方最近一次表态的时间 |
| `cdms` | 消息历史，最新的在最后 |

## 申报状态

`claim_status_*` 是协同层，值得把它的含义说准：

| 取值 | 含义 |
|---|---|
| `none` | 没有申报记录 |
| `assumed` | 假定该方会机动 |
| `claimed` | 该方声明要机动 |

它是**被记录**的，绝不靠推断。从卫星近期行为推断"对方大概会机动"，是在猜测别人的
运行安排并据此行动。

## 取用

```bash
curl --key client.key --cert client.crt 'https://<host>/api/v2/event/<uuid>'
```

响应里带 `cdms`，所以一个请求同时给出当前风险和它的来历。对持续时间很长的交会，
用这个而不是反复读流：一行而不是几百行。

## 弃用的 v1 视图

`GET /api/v1/event` 仍然存在，因为按旧教程写的客户端会调它。它只含调用方运营方的数据，
字段也只是子集。新代码请用 `/api/v2/event/:id`。
